# Code and results audit (2026-11-03)

**Scope.** Six independent reviews covered:
1. data and splits;
2. model and training;
3. metrics and statistics;
4. baseline codecs;
5. TTS and factorization;
6. provenance and reproducibility.

Every finding below marked *verified* was re-checked against the code and the
committed result files. No code or result was changed by the audit.

**Bottom line.**
- No reported number is fabricated, produced by a smoke or dummy config, or
  attributed to the wrong run.
- The metric code and generation code are correct, and every number recomputes
  from its per-utterance files.
- Fixes are needed before the freeze:
  - one table uses an oracle protocol;
  - the tables are stale;
  - one comparison is not like-for-like;
  - the streaming latency is understated;
  - several claims need precise wording;
  - one training bug affects the non-causal arms.

## A. Must fix before the freeze

1. **Oracle speaker vector in the mel-domain FaCT rows and the "paired mel-L1
   difference" table** (verified).
   - `scripts/collect_results.sh` feeds `results/fact_recon/*_<set>.json` to
     those rows and to the paired table.
   - Those files were made with `eval_fact_recon.py --spk-ref` at its default,
     `full`: the speaker vector comes from the target utterance itself.
   - LibriSpeech mel-L1 for fact_main full is 1.194 with the oracle vector and
     1.456 with `spk_ref=other`.
   - Not affected: the vocoded rows (`fact_*_spkother`, `*_T0.3G2.0`, `*werSel`)
     and the stage-D rows (`factwave_*`). Those use `spk_ref=other`, and every
     headline WER/UTMOS/SIM number comes from them.
   - Fix: build those rows from the `*_spkother` files, or drop them.
2. **Committed tables are stale** (verified).
   - `results/tables/recon_*.md` were last built on 2026-10-26 (commit
     2a14aa1); the results go up to 2026-11-02.
   - Missing: every stage-D, chunk2, distill, disjref, noncausal and ssl_nc row,
     and the baseline UTMOS/SIM values.
   - Bootstrap CIs depend on row order because one RNG is shared across cells.
   - Fix: regenerate everything and seed each cell independently.
3. **Emilia mel-L1 / energy r / F0 are not like-for-like for 16 kHz codecs**
   (verified).
   - `scripts/eval_baselines.py` scores each codec against the reference
     resampled to that codec's rate.
   - On 24 kHz Emilia, FocalCodec, BigCodec and XCodec2 are therefore scored
     with the 8–12 kHz bins empty in both reference and output, which favours
     them.
   - LibriSpeech (16 kHz source) is unaffected.
   - Fix (no GPU): report mel-L1 on LibriSpeech only, or mark Emilia mel-L1 as
     not comparable for 16 kHz systems.
4. **Streaming latency is understated** (verified;
   `tests/test_causal_generator.py` itself asserts lookahead = L + 2 frames).
   - The stage-D generator's iSTFT overlap-add adds 2 frames (40 ms) on top of
     the convolution lookahead, so the generator alone looks ahead:

     | Variant | Convolutions | iSTFT | Total |
     |---|---|---|---|
     | la4 | 80 ms | 40 ms | **120 ms** |
     | la8 | 160 ms | 40 ms | **200 ms** |

   - End to end, the worst-case algorithmic latency is about 120 / 200 / 280 ms
     for la0 / la4 / la8. It is made up of the token frame (60 ms worst case),
     the STFT half-window (20 ms), the convolution lookahead and the iSTFT
     (40 ms).
   - `docs/DEMO_PLAN.md`'s "about 181 ms" for la4 is wrong; it is about 200 ms.
   - FocalCodec-Stream's latency must be quoted on the same definition.
5. **The full-view bitrate is an information bound, not a bitstream.**
   - The residual is a continuous, power-limited, noise-perturbed channel
     capped at 8 nats/frame, which gives ≤ 144 bps.
   - So "0.42 kbps" must be stated as "0.28 kbps tokens + residual of
     ≤ 0.14 kbps capacity", not as a coded bitrate.
   - The tokens-only view (0.28 kbps) is a true bitrate.
6. **Wording in table titles** (verified).
   - The Emilia test table says "speaker-disjoint". The split is group (B,S)
     disjoint, and a recurring person can appear in two groups.
   - Titles say 5,000 (test) and 2,000 (dev) utterances. The tables use the
     same-speaker-partner subsets, 3,783 and 1,158.
7. **Smoke and pilot files sit next to real results.**
   `results/baseline_recon/*`, `vocoder_ceiling.json` and
   `fact_recon/pilot_*` (200 utterances each), and the pilot/v2_nodrop rows in
   `tripwires.md`. Move them out of the frozen set.

## B. Claims to state precisely in the paper

1. **TTS:**
   - FaCT's decoder receives the prompt's continuous speaker vector; Mimi-2's
     decoder receives only codes.
   - So part of the SIM and UTMOS gap is the decoder, not the LM.
   - Report codec resynthesis ceilings next to it (already measured:
     LibriSpeech tokens-only WER 4.74 vs Mimi-2 8.06) and disclose the side
     information.
2. **Prosody control:**
   - pitch_kept does not differ significantly from Mimi-2 (FaCT − Mimi-2
     +0.03 [−0.03, +0.09]), and Mimi-2's absolute pitch diversity is higher.
   - words_moved (0.46 vs 0.82) is partly inflated by Mimi-2's ASR noise floor.
   - The CIs resample utterances, but there are only about 40 prompts (one per
     speaker), so they are too narrow. Re-run the bootstrap at speaker level
     (CPU only).
3. **Factorization:**
   - The 0.00 st content-path shift is real.
   - But content-token agreement under a pure pitch shift is only 0.39–0.41,
     lower than Mimi-2's first codebook (0.64).
   - Claim "the decoder takes pitch only from the prosody tokens", not "the
     content tokens are pitch-invariant".
4. **`spk_ref=other`:**
   - FaCT gets a speaker vector from a second utterance as side information.
     It is not counted in the bitrate, and no baseline gets an equivalent.
   - On LibriSpeech the partner is usually from the same chapter.
5. **Speaker similarity** uses `wavlm-base-plus-sv`, not the WavLM-large/ECAPA
   model common in papers, so the absolute values aren't comparable to
   published SIM. The docstring calls it "WavLM-ECAPA".

## C. Training bug (non-causal arms)

**Non-causal transformers attend to padded frames** (verified).
- `fact/modules/transformer.py`: with `causal=False` the mask is all ones, and
  there is no key-padding mask.
- During training, the noncausal and ssl_nc runs (encoder, and decoder where it
  is non-causal) attend to the batch padding. At evaluation there is no padding.
- Causal and chunked arms are unaffected, because padding is at the end.
- The noncausal and ssl_nc results are real, but come from models with this
  mismatch. It most likely handicaps them, so the claims are conservative.
- Options:
  - disclose it;
  - or fix it and retrain both arms (stage A, about 400K steps each, then their
    decoders), which needs GPUs.

## D. Reproducibility gaps

- **Code version:** no git commit is recorded with any job, log or checkpoint,
  and jobs run whatever HEAD the runner has.
  - Fix going forward: write `git rev-parse HEAD` into every log and result.
  - For past runs: the result→request→log chain is intact for all 190 completed
    eval specs, but not to the commit.
- **Logs:** they keep only the last 400 lines (356 of 929 were cut, including
  17 of 30 stage-D headers).
- **The collector** commits all of `results/` under one request's message, so
  commit messages don't match the files they carry. File names still identify
  the request.
- **Runner environment:** it leaks into jobs (sbatch exports everything). No
  stray variable affected the checked logs.
- **Dependencies and models:** dependencies are `>=` ranges with no lock file;
  Hugging Face model revisions are not pinned.
- **Checkpoints** are on SCRATCH (about 40-day purge). Only the four main
  stage-A runs have a copy elsewhere.
- **Manifests:** `dev.tsv` and `test.tsv` aren't committed; their utterance ids
  are recoverable from the result files.
- **Other:** TF32 is on, so GPU runs aren't bit-identical; resume reseeds
  instead of restoring RNG state.

## E. Minor (no effect on current numbers)

- **`fact_wave` bitrate:** it would under-report the bitrate for an uncapped
  residual (all current rows are capped).
- **Resume guards:** they ignore config or run keys missing from the old
  checkpoint (trainer and stage D).
- **Quality-filter merge:** it doesn't check each part's `num_parts`; the output
  is unused.
- **`reference_partners`:** it can pair a key with itself if keys repeat; keys
  are unique in all results.
- **Silent drops and fallbacks:**
  - F0 RMSE silently drops utterances with no jointly voiced frames (1–12 per
    system).
  - `prepare_eval_set.py` falls back to an empty transcript and doesn't assert
    2,620.
  - `manifest.py` writes an empty transcript when the JSON is bad.
  - One dev utterance has an empty reference.
- **Whisper:** its temperature fallback is unseeded.
- **Unused or unchecked code:**
  - `train.ema_decay` is unused.
  - Stage B is broken but unused.
  - The slow-prosody ablation has 80 ms of lookahead; it's unused.
  - SSL input with `causal=True` isn't refused.
- **FACodec:** the wrapper is still a stub that refuses to run, so it needs
  implementing before the postponed baseline.

## Verified correct

- **Splits:**
  - Train, dev and test are group-disjoint with a stable md5 hash.
  - LibriSpeech test-clean has all 2,620 utterances, with transcripts aligned
    (copy-synthesis WER 2.35%).
  - LibriTTS is train-only: 354,780 utterances, no test-clean speakers.
  - Speaker partners are never the target.
- **Causal encoder and lookahead:** the causal encoder is strictly causal, and
  chunk lookahead is exactly (c−1)×80 ms.
- **Bitrates:** FSQ code counts are 8192 and 625; the tokens-only and full
  bitrates are correct; every baseline's bitrate is correct.
- **Training and stage D:**
  - Loss masking, DDP, checkpoint save/resume and `--init-from` are correct.
  - Stage D freezes the tokenizer, and its utterance windows are frame-exact.
  - Distillation and WavLM are training targets only.
- **Metrics:** WER (normalizer, edit distance, corpus aggregation),
  UTMOS/SIM/PESQ/STOI/F0 procedures, and the paired bootstrap on shared keys.
- **Recomputed results:** all 150 LibriSpeech/Emilia aggregates, the TTS numbers
  (2.563 / 3.482 / 0.914 vs 8.538 / 2.527 / 0.827, 1,237 utterances, 8 shards,
  no duplicates), the prosody summary and the factorization merge.
- **TTS model and fairness:**
  - Generation matches a full forward pass (30 random models, with and without
    fixed stream 0); the delay pattern and masks are correct.
  - The prompt is never the target; dev and test are separate.
  - Both LMs use the same data and steps; the parameter difference (3.1%) is
    only in the embeddings and heads.
- **Baselines:** FocalCodec "causal" configs are the streaming models (chunked
  causal attention with 3-frame lookahead).
- **Excluded runs:** the segment-trained non-causal decoders' files are gone.
- **Queue:** dependency, cancel, hold and account logic are correct.
- **Tests:** 271 pass (the PESQ/STOI module is skipped here because `pesq`
  isn't installed); none is vacuous.
